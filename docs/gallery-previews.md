# Gallery live previews

The gallery homepage and its hero, style, layout, public-icon, Character theme,
and runtime-catalog pages preview the **existing HTML diagram runtime**. An SVG
loaded as an image cannot execute GSAP icon performances. The new preview layer
does not replace those performances with a card bounce or another generic effect.

There are 64 unique HTML targets across these seven gallery surfaces. The Hero
Demo uses Dify in Minimal Light and Deep Tech, with bilingual case-study pages.
Both styles share the same pinned architecture and evidence. The previous
synthetic hero remains available in `showcase_manifest.json` as `legacy_hero`;
its artifacts are not deleted. Dify case pages and the curated README showcase
use their own animated WebP previews and delivery/acceptance records.

## Behavior

- Visible cards load same-origin HTML in a non-interactive preview frame. Open
  the card to use the full viewer, its controls, and original SVG download.
- Leaving the viewport or hiding the browser tab releases the frame and its
  timers. The gallery does not run every diagram simultaneously.
- **Pause previews** switches all cards to static posters. **Play previews**
  resumes visible cards. `prefers-reduced-motion: reduce` always uses posters.
- No JavaScript, unavailable GSAP, or a failed/slow runtime keeps the static
  poster and ordinary HTML link available. No external dependency is installed.
- Posters are derived from the original SVG, settling entrance fades, removing
  SMIL, and disabling CSS animation. Icon geometry, labels, and relationships
  are preserved. These are presentation fallbacks, not a new semantic review.
- Dify uses an explicit `data-preview-poster` pointing at its delivered static
  SVG. That existing asset is hashed and reused, never regenerated by the gallery.

## Rebuild only previews

```bash
PYTHONPATH=src python3 scripts/build_showcase.py --indexes-only
```

This writes the seven index pages, `*.preview.svg` posters, shared preview
assets, and `gallery/preview-manifest.json`. It does not regenerate diagram
specs, SVG/HTML diagrams, source-backed evidence, media, frozen releases, or
review records. The preview manifest binds each HTML, original SVG, and poster
by SHA-256. Both full showcase builders also emit the preview layer.

## Verify

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -p 'test_*gallery*.py'
node scripts/verify_gallery_previews.mjs
PYTHONPATH=src python3 scripts/check_asset_budget.py
```

The browser gate uses HTTP and the actual card frames. It samples every eligible
icon's SVG parts during natural playback, checks playing timelines and preview
fit, and verifies desktop/mobile widths, pause/resume, reduced motion, missing
dependencies, and the no-JavaScript static fallback. Reports/screenshots are
written under `outputs/gallery-motion/`; CI runs the same gate. To use an
already-installed Chrome locally, set `ANIDIAGRAM_BROWSER_CHANNEL=chrome`.
The title-entry-only example is checked as a completed one-shot; it has no icon
performance and is not converted into an artificial loop. Unlinked legacy
diagram outputs and frozen approval records are not migrated by this refresh.

Passing animation checks does not establish architectural correctness or human
visual approval. Keep existing semantic-review and source-evidence boundaries.
