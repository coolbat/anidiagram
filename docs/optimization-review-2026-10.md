实施与验证记录见 [optimization-implementation-2026-10-07.md](optimization-implementation-2026-10-07.md)。以下实测表保留原观察，复核修正如下：

- RAG 的确定缺陷是两组重叠和连线穿节点；原编译坐标未证明节点越出画布或所属分组。泳道预设存在真实节点越界。
- 质量检查只能验证几何和有限诊断；简报已知词覆盖率不能证明语义准确。未知词、否定句、关系顺序和源码事实仍需复核。
- 分组嵌套或共享成员可能有意重叠，长斜线也不一定错误；仅无关分组部分相交、显式所属关系越界等确定问题设为 error。文本碰撞为估算 warning。
- 数据包 packet/comet/stream、随线宽缩放和运动预算已有实现；C2/C4 应扩展现有系统，而非重建。
- 首屏验收改为无裁切且居中；宽度利用率受纵横比影响。显式 `--readable-labels` 保留原尺寸滚动。

- 后续可先在 P1 做有限路由/标签修复，优先减少 P0 已暴露的警告，再进行 P2 布局引擎重构。

第二轮复核修正（2026-10-07，回归见 `tests/test_rule_planner_recheck.py`）：

- 英文规则曾对测试句式过拟合：评审原句只得到 8 实体并抽出 "Each service"、"its own database"、"raises alerts" 伪实体。现已支持 `places an order through X into Y`、`On … success` 条件、`Each service … its own database` 展开，评审原句为 15 实体 / 12 关系，"raises alerts" 列为未解析。
- 扩展请求 / 读取 / 写入 / 消息动词（如 forwards … to、talks to、reads from、stores … in、访问、发给、读取、推送到、`把 … 发给`），动词出现在实体名内时取首个有效位置。
- 否定句不再把"直接"等副词粘进实体名；"Billing" 与 "billing service" 合并为同一实体。

## 1. 结论摘要

工程底子扎实：测试全绿、6 个 HTML 产物浏览器零报错，三种动效模式、中英文、事务式交付均可用。
影响"精美度"和可信度的主要问题不在风格皮肤，而在三处：

1. **语义抽取**：`--text` 一句话生成是固定 Agent 模板，不理解业务需求。
2. **布局与连线**：连线压节点、压分组标题与标签，存在分组重叠、节点越界。
3. **动效**：图标各自循环、缺少因果叙事；讲解模式聚焦太弱。

以上问题质量检查均报 0 错误——质量门禁的盲区是第一优先级。

## 3. 问题与优化方案

### 3.1 可信度

**A1 一句话生成是模板。** `planner.py` 只匹配 memory / tool / safety / loop 等关键词后套 Agent 模板。
- 短期：增加"简报覆盖率"检查——按公开有限词表比对简报与模板实体，并检查未识别文本片段；覆盖不足或不可评估时输出警告并提示改用 `--plan` 或 Skill 工作流。
- 中期：规则化抽取"A 调用 B / A 写入 C / 通过 X 通知 Y"句式；可选接入 LLM 规划器，模板只作兜底。
- 修正标题与说明生成，不再拼接简报原词。
- README 快速开始使用的正是这条路径，需同步调整示例或加说明。

**A2 质量检查盲区。** 需新增规则：
- 分组与分组相交；
- 节点越出所属分组 / 泳道；
- 连线穿过非端点节点；
- 连线压住边标签或分组标题；
- 非正交长斜线；
- 徽标与标签重叠。

### 3.2 布局与排版

**B1 连线避让。** 引入正交路由与障碍避让（参考 ELK layered / libavoid）；并行连线固定间距（约 8px）；标签加底色描边并放在连线中段空白处。

**B2 首屏适配。** 1440×900 下 c1/c3/c5 被裁切，c2/c4/Dify 画布只占约 60% 宽度。加载时默认"适配窗口并居中"，"重置视图"回到该状态。

**B3 节点卡片层级。** 说明最多 2 行（超出加宽或截断 + 悬停全文）；文字左对齐；统一标题/说明/标签三级字号；节点与连线序号徽标只保留一种。

**B4 泳道与特殊节点。** 节点避开泳道标题区、不越界；菱形决策节点图标与文字分区；暗色风格增加层次（表面明度阶梯、细描边、柔和阴影）。

**B5 RAG 布局缺陷。** 排查 `layered` 自动布局在多分组 Plan 下的分组边界计算与节点分配。

### 3.3 动效设计

**C1 入场编排。** 现状：连线先出现，节点逐个缓慢淡入（约 800ms 时画面全是指向空白的箭头）；组边框有灰色模糊色块、标题背后有高亮底残影。
- 顺序：分组框 → 节点（约 50ms 间隔、缓出）→ 连线在两端都出现后再描画。
- 总时长 ≤ 1.2s。
- 去掉组边框扫光，或改为一次性细线扫光。
- 默认 `.svg` 不依赖入场动画即完整（截图、打印、嵌入不会拍到半透明态）。

**C2 数据包语义系统。**
- 按关系类型区分：同步请求/响应用实心点 + 短拖尾；异步/队列用虚线 + 延迟出发；持续流用连续流线；失败/拒绝用红色 + 回弹。
- 尺寸随线宽缩放，提高对比度。
- 按路径长度匀速移动，不用固定时长。

**C3 到达反馈与事件驱动。** 数据包到达时目标节点 150ms 轻脉冲或端口涟漪，再触发图标表演。即路线图中的 `event-driven` 模式，建议作为下一版默认候选（仍需显式开关，遵守 `runtime-motion-roadmap.md` 的产品规则）。

**C4 运动预算与全局节拍。** 只有主流程常驻动画，次要关系静态、悬停才动；同时运动元素默认 ≤ 3–5 处；所有循环对齐统一周期（如 4s）。

**C5 讲解模式升级。** 现状每步仅起点放大 2.5%、连线重描、终点放大 3.5%，无说明文字。
- 非当前元素降至约 25% 不透明度；
- 镜头平移缩放到当前步骤区域；
- 底部讲解卡片：第几步/共几步、关系标签、条件、`source_refs` 源码链接；
- 键盘左右键翻页、带停顿自动播放、进度圆点。

**C6 易读模式。** 保留；超过 N 个节点时提示建议启用，或由显式配置开启自动策略；保留用户选择。

### 3.4 展示外壳与 Gallery

- **D1 工具栏**：11 个按钮分为播放控制 / 模式分段切换 / 缩放三组，悬浮半透明；下载、复制链接收进菜单。
- **D2 外壳配色**：外壳背景跟随图的风格，避免深色外框配浅色图。
- **D3 悬停高亮**：上下游高亮从 reader 模式下放为所有 HTML 的默认轻量能力。
- **D4 Gallery 首屏**：放一段 6–8 秒讲解模式录屏作为主视觉，下方再放风格与布局矩阵。
